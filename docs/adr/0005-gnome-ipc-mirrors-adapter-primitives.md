# GNOME IPC mirrors adapter primitives

V1 exposes `GetCapabilities() -> as`, `GetFocusedWindow() -> (bsiiuu)`, `GetDisplays() -> a(siiuu)`, `MoveFocusedWindow(iiuu) -> ()`, atomic `RegisterHotkeys(as) -> ()`, and `HotkeyPressed(s)` on `org.window_zones.Gnome1`; the focused-window boolean marks the remaining fields absent when false. Optional `transition-metrics` enables `GetLastTransitionMetrics() -> (dd)` for request/completion milliseconds from the same D-Bus caller's last successful move. Move completion waits for settled geometry and the selected visual transition; restoration precedes the destination request. Caller disconnect clears its metrics.

The Rust App retains zone, directional-neighbour, display-action, and binding semantics. Empty registration and client disconnect provide unregister/cleanup without a second lifecycle API. IPC payloads use native typed D-Bus values mapping to the existing geometry and hotkey types; JSON and variant dictionaries remain out of scope for IPC. Transport failures use standard D-Bus error names; domain cases use small project-defined errors. One App owns the registered hotkey set at a time; other clients can inspect and request window moves but receive `Busy` on registration. Concurrent moves of the same window cancel the superseded request explicitly.
