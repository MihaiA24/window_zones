# GNOME IPC mirrors adapter primitives

The companion exposes only `GetCapabilities() -> as`, `GetFocusedWindow() -> (btiiuu)`, `GetDisplays() -> a(siiuu)`, `MoveWindow(tiiuu) -> ()`, atomic `RegisterHotkeys(as) -> ()`, and the `HotkeyPressed(s)` signal on `org.window_zones.Gnome2`; the focused-window boolean marks the remaining fields absent when false, and the `t` is the Mutter window id that `MoveWindow` addresses (ADR 0009; `Gnome1` carried a display string and moved whichever window had focus). The Rust App retains zone, display-action, and binding semantics. Empty registration and client disconnect provide unregister/cleanup without a second lifecycle API. Payloads use native typed D-Bus values that map directly to the existing `Rect`, `FocusedWindow`, `DisplayGeometry`, and hotkey types; JSON and variant dictionaries are out of scope. Transport failures use standard D-Bus error names; only domain cases such as unsupported capability, invalid window state, or a window that is gone get small project-defined errors. One App may own the registered hotkey set at a time; other clients can inspect capabilities and request stateless window moves but receive `Busy` if they attempt registration.
