# GNOME IPC mirrors adapter primitives

V1 exposes only `GetCapabilities() -> as`, `GetFocusedWindow() -> (bsiiuu)`, `GetDisplays() -> a(siiuu)`, `MoveFocusedWindow(iiuu) -> ()`, atomic `RegisterHotkeys(as) -> ()`, and the `HotkeyPressed(s)` signal on `org.window_zones.Gnome1`; the focused-window boolean marks the remaining fields absent when false. The Rust App retains zone, display-action, and binding semantics. Empty registration and client disconnect provide unregister/cleanup without a second lifecycle API. Payloads use native typed D-Bus values that map directly to the existing `Rect`, `FocusedWindow`, `DisplayGeometry`, and hotkey types; JSON and variant dictionaries are out of scope. Transport failures use standard D-Bus error names; only domain cases such as unsupported capability or invalid window state get small project-defined errors. One App may own the registered hotkey set at a time; other clients can inspect capabilities and request stateless window moves but receive `Busy` if they attempt registration.
